The mug shop now needs to keep one mug for customers who buy in person. An online order may take stock from two mugs to one, but it must leave that final mug alone. This changes an agreement we deliberately tested: buying the last mug used to be valid.

Use the shop from [Test shop behavior](../test-behavior/), including its decision, replay, stored-command, and live HTTP checks. Each order still buys one mug, and opening a shop still records three. We will change which orders the shop accepts, then use those checks to distinguish the intended difference from an accidental regression.

## The new agreement

Before asking the agent to edit code, revise the behavior table. The new rejection text below is our chosen reply for the reserve policy; the existing replies retain their meanings.

| Starting situation | Previous decision | New decision | Stock after new decision |
| --- | --- | --- | --- |
| Three mugs | Accept | Accept | 2 |
| Two mugs | Accept | Accept | 1 |
| One mug | Accept | Reject: `Reserved for in-person sales` | 1 |
| Zero mugs | Reject: `Sold out` | Reject: `Sold out` | 0 |
| Shop does not exist | Reject: `Shop not found` | Reject: `Shop not found` | No shop row |

Only the one-mug outcome changes. The two-mug row checks the other side of that boundary: reserving one mug must not accidentally reserve two. Zero stock remains a useful case even though new online orders stop at one. An existing shop may already have sold every mug under the old policy.

Give your agent this bounded task from the project root:

```text wrap
Follow the project's active NeoHaskell guidance. Change online PlaceOrder so one mug remains for in-person sales. First update the behavior table and checks: stock 3 and 2 accept one OrderPlaced; stock 1 rejects with Reserved for in-person sales; stock 0 still rejects with Sold out; missing shop still rejects with Shop not found.

Show the new reserve check failing against the old decision, then make the smallest decision change. Keep accepted event payloads and stream choice unchanged. Preserve ShopOpened, OrderPlaced, replay, AvailableStock, routes, and Feature/App composition. Do not rewrite recorded history.

Update stored-command checks to accept two orders from opening stock 3 and reject the third without changing history or stock 1. Keep exact payload assertions and distinct rejection checks. Keep the old replay sequence ending at zero as a historical compatibility check.

Update tests/integration/http-orders.hurl to check live stock 3, 2, 1, reserve rejection, missing-shop rejection, and unchanged stock 1. Retry only query reads with a bounded deadline. Run neo --ci test and show the decision diff, changed expectations, actual results, and any checks skipped after a failure.
```

Changing an expected result is justified here because we changed the agreement first. In the previous lesson, the same last-mug rejection was a bug. A failing test alone cannot decide which policy the shop should have; that decision belongs to you.

## The decision diff

Ask the agent to show the change in `src/Shop/Commands/PlaceOrder.hs`. The old acceptance condition was:

```haskell wrap
if shop.availableMugs > 0
```

The new decision needs to distinguish a sold-out shop from a shop holding its reserve. This excerpt shows the decision inside the `Just shop` branch, with the surrounding function omitted:

```haskell wrap
if shop.availableMugs <= 0
  then Decider.reject "Sold out"
  else if shop.availableMugs > 1
    then Decider.acceptExisting [
      OrderPlaced OrderPlaced.Event {
        entityId = shop.shopId
      }
    ]
    else Decider.reject
      "Reserved for in-person sales"
```

The first condition preserves the sold-out reply. The second accepts an order only when subtracting one will leave at least one mug. At stock one, neither condition permits an order, so the decision returns the new reserve reply. The `Nothing` branch must still reject with `Shop not found`.

Read the accepted branch too. It still proposes exactly one `OrderPlaced` for the same shop in the existing stream. No reserve event is needed: rejecting a request records no new fact. The shop's stock calculation still subtracts one for each accepted order.

Use `neo ide` to inspect the shop in **Ungrouped**, then choose **Fit View**. Trace `PlaceOrder` to `OrderPlaced`, and follow `OrderPlaced` into `AvailableStock`. The connections should remain the same. This policy changes the decision inside that route, rather than adding another event or replacing the query. The graph helps you inspect that scope; the tests establish which requests now pass through it.

## Old history and new requests

A shop that previously accepted three orders from opening stock three has a real history ending at zero. Reserving a mug today does not make the third recorded order disappear. Keep `tests/Shop/ShopStockSpec.hs` replaying the original sequence:

```text wrap
Initial state       0
ShopOpened          3
First OrderPlaced   2
Second OrderPlaced  1
Third OrderPlaced   0
```

Replay applies accepted facts; it doesn't ask today's decision to approve them again. Changing `update` to stop subtracting at one would misrepresent a mug already sold. Changing `AvailableStock` to report one for that history would give the same false answer. Both calculations remain unchanged, so a historical zero-stock shop still reports zero and rejects a new order with `Sold out`.

A fresh shop follows the new policy instead. In `tests/Shop/PlaceOrderSpec.hs`, two commands should succeed, leaving one `ShopOpened` and two `OrderPlaced` events. Save that history before the third request. The reserve rejection must leave the complete recorded payloads unchanged, as must the missing-shop rejection. The query handler check should now expect one mug after both requests. Remember that manually driving this updater checks query maintenance, while the Hurl scenario checks the running subscription.

## Evidence for the changed boundary

With the revised expectations and the old decision, the verified shop failed two of its twelve examples: the reserve decision and the stored-command check. Neo skipped Hurl after that failing unit suite. Applying the decision change made those checks pass.

Run `neo --ci test` after reviewing the diff. A report should connect each changed expectation to the table, rather than merely announce that the suite is green. In the verified shop, the updated checks produced these results:

| Check | Expected after the policy change | Observed |
| --- | --- | --- |
| Decisions at stock three and two | Accept exactly one event in the existing stream | Passed |
| Decision at stock one | Reject with the reserve reply | Passed |
| Zero stock and missing shop | Preserve distinct original replies | Passed |
| Historical replay | Preserve counts 0, 3, 2, 1, 0 | Passed |
| Stored commands and live HTTP | Two accepted orders, reserve rejection, stock stays one | Passed |

For the browser check, use the running application's built-in documentation as in [Place an order over HTTP](../http-orders/). Open a fresh shop with a new chosen identifier, then use **Test Request**, **Body**, and **Send** on `place-order` with that identifier. The first two requests succeed; the third returns `Reserved for in-person sales`. Read the keyed `AvailableStock` query again until its asynchronous update appears: it should settle at one. Repeating the rejected request must not consume that mug.

Keep the source diff and actual check output with the agent's report. A request to change a rule should end with evidence for that rule and for the behavior it preserves.
