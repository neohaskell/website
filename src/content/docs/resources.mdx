NeoHaskell is an AI-first programming language under active development. Start with a small behavior you can describe and check. The Counter starter gives you a concrete application to inspect before extending it with your agent.

## Releases and compatibility <a id="releases-and-compatibility" />

A CLI release, a framework source revision and an agent-skills release identify different parts of your working environment. Neo runs the development commands, your project's dependencies select the framework APIs, and agent skills guide the work. Updating one does not establish that the others are compatible.

<ProjectCompatibility />

When investigating a failure or upgrading a project, record the installed Neo version and the dependency settings in `neo.json`, including any local source override. Follow [neo.json and dependencies](../reference/configuration/project/) to identify the effective source. A successful build checks that the combination compiles; behavior tests check the cases they actually execute. Neither establishes a compatibility promise for every release or application.

The [Neo release history](https://github.com/neohaskell/NeoHaskell/releases) describes published changes. A source link pinned to a commit describes that revision, which may include work absent from your installed release. The separate [agent-skills releases](https://github.com/neohaskell/skills/releases) describe changes to instructions. Match API guidance to the framework source your project uses rather than assuming the newest instructions match every project.

## Before relying on an application <a id="before-relying-on-an-application" />

The starter uses an in-memory event store by default. Its recorded events disappear when that process ends. Persistent event history and persistent query storage are separate configuration choices; use [Keep events across restarts](../guides/storage/) and [Persist and rebuild queries](../guides/storage/query-rebuilds/) when you need data to survive a restart.

Your application also owns its access rules. Read [Authorize a command](../guides/authorization/) and [Restrict query results](../guides/authorization/query-access/) and test the allowed and rejected cases. An AI agent helps implement these rules; it does not decide your application's policies at runtime.

Published source and releases let you inspect what is available. They do not by themselves establish production readiness for your application.

The [framework source license](https://github.com/neohaskell/NeoHaskell/blob/414602b9510a92dfac647bc68d6afadfb594502c/LICENSE) is available alongside the code. Check each tool's own license when choosing dependencies.

## Follow changes and get help <a id="follow-changes-and-get-help" />

If setup or a request fails, [Setup and build errors](../reference/errors/) and [Startup and request errors](../reference/errors/runtime/) connect symptoms to a recovery check. For a problem you cannot resolve, [browse reported issues](https://github.com/neohaskell/NeoHaskell/issues) or [ask the community on Discord](https://discord.com/invite/wDj3UYzec8). Include the intended behavior, the smallest failing example, the diagnostic, and your CLI and framework versions. Remove tokens, passwords and private application data before sharing logs. Community discussion and a published release do not establish a support response time.

## Contributing reusable work <a id="contributing-reusable-work" />

A provider integration can be useful beyond the application that first needed it. [Create a reusable integration](../guides/integrations/create-reusable/) separates the provider protocol from application-owned commands and events; [Manage integration resources](../guides/integrations/resources/) covers resource ownership and cleanup. Contribute generic integrations and their tests to the current [NeoHaskell monorepo](https://github.com/neohaskell/NeoHaskell), following its [contribution guide](https://github.com/neohaskell/NeoHaskell/blob/414602b9510a92dfac647bc68d6afadfb594502c/CONTRIBUTING.md). Have your agent read the repository's `AGENTS.md` before making a change.

Keep application policy in the application. A reusable integration should describe the provider's inputs, results and failures, with tests that make its behavior inspectable without private credentials. Neo packages are a future distribution direction; use the monorepo contribution route for shared integrations today.
